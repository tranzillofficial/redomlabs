# Architecture
Next.js App Router, bilingual /ar and /en, RTL Arabic. Self-hosted Tajawal and Manrope fonts. Light theme defaults; indom-theme stores the visitor preference.

Routes: home, about, services, products (own products), work (client portfolio), contact, privacy, terms, storage. Legacy projects redirects to products; legacy aion redirects home with the welcome assistant open. No product images appear on the landing page. No published client case studies or verified product URLs have been supplied.

WelcomeChat is a text-only, user-opened dialog with keyboard focus containment, Escape, quick questions, clear conversation and allowlisted page links. No avatar, 3D, voice SDK, automatic popup or microphone access. Memory is in-page only.

POST /api/chat uses AI SDK 6 with Vercel AI Gateway and google/gemini-2.5-flash-lite, verified in the live model catalog on October 2, 2026. Vercel OIDC supplies deployed authentication; no client secrets. Short bounded replies, eight-message maximum, request validation, timeout and per-instance rate limiting. Rate limiting is not distributed across instances. JSON routes from the model are validated against the site sitemap. Provider failure returns a clearly labeled knowledge-based site guide with useful navigation links. No tools perform external actions. Preview test returned fallback. The team dashboard shows $0 gateway credit and requires card verification to enable free credit. No card was added or billing change made. Live AI availability remains blocked until the owner activates Gateway.

Brief downloads a local text file only; it does not submit leads. No analytics, advertising trackers, application chat database or payment functionality. Hosting/model providers may keep operational logs. The privacy policy describes these limits. A dedicated privacy contact and case studies remain publication inputs, not invented content.

## Admin interface prototype, October 3, 2026

Illustrative anonymous sample customers and activity are explicitly labeled, and real metric counts are not fabricated. No visit tracking, survey endpoint or customer data collection was introduced. Identifying a customer from visits alone is not possible.

AION launcher is a compact custom SVG wordmark inspired by the reference character label: open chevron A with mint dot, I, rounded O and angular N, plus an AI chip icon. No avatar returns to the website. Assistant knowledge contains MenuzQR only.

Account security is a live setting: server-validated admin identity, current-password reauthentication for the same user, matching new-password confirmation (10–200 characters), provider updateUser, global sign-out and cookie removal. No password is returned to the browser or stored in the repository.

Public SiteEntrance owns the document-load splash (4 seconds: 1.4-second assembly, 2-second completed-logo hold, 0.6-second exit); internal navigation keeps its played state, while refresh/new visits replay. Existing SVG paths move using per-glyph transforms and discrete visibility, with no letter-opacity fade. A gentle camera push ends the cream/theme-aware full-screen entrance. Powered by AION sits below. Site content is inert during the hydrated entrance, restores scrolling after removal and is usable without JavaScript via noscript CSS. Reduced-motion skips the splash. Header, footer and hero logos remain static; no replay control. AION launcher is now 84×44px, icon-free, with an 8px corner radius.

The final camera push synchronizes with 22 subtle SVG radial streaks moving outward from the center. Theme colors, reduced-motion skip and once-per-document behavior are retained.

## CRM and scoped administration — October 14, 2026
`crm_customers` stores customer/service details, currency, agreed total and total paid (including deposit). `remaining_amount` is a numeric generated column with constraints preventing negative amounts or overpayment. Stages are customer, potential and follow_up; dates and notes support repeat contact. Global name/phone/business/service search and stage filters use server-side pagination. CRM conversion from a proposal request creates a potential lead with zero agreed amount; request estimates never become agreed amounts automatically. The unique request reference prevents duplicate conversion.

`admin_staff` maps Supabase Auth identities to owner-managed names, enabled status and section permissions. Existing server-managed `indom_admin` users are owners. Login validates Auth plus the current staff row; server actions enforce module access. Private `redom_private.has_access` reads the current Auth owner metadata and staff table through a constrained definer with no user-id argument, so disabling/revoking a scope takes effect without waiting for JWT refresh. RLS protects CRM, requests, staff and existing content modules. Authenticated staff cannot grant themselves permissions, and the private contact trigger stamps the authenticated actor/name/time; browser input cannot spoof attribution. Legacy permissive proposal policies were replaced with scoped policies while preserving passcode/public-catalog RPCs.

`proposal_request_reads` stores each user's explicit request openings. A scoped invoker RPC counts unread requests independently of the paginated inbox; the sidebar refreshes on mount, focus, mutations and every 30 seconds. Deleting a request cascades its read receipts and detaches a converted CRM lead. Contact attribution is shared across staff; unread state is per user.

Next.js team actions call `admin-team` Edge Function using the validated owner's session. The function validates the owner with Auth, uses its built-in server-only service-role environment to create confirmed password accounts without sending mail, and stores permissions in the staff table. It will not edit owner accounts; if staff insertion fails, it deletes the newly created Auth account. Names, scopes and enabled status can be edited; team administration is owner-only. Supabase Edge source is excluded from the Node TypeScript compilation because it runs in Deno.

Deployment order: existing `redomlabs-setup.sql`, proposal request/public-general setup, then rerunnable `crm-team-setup.sql` and the admin-team Edge Function. The connected production schema has already received this change. No remote service secret or customer data is committed. Browser tests use a local REST/Auth contract fixture; separate live SQL transactions test actual production RLS and constraints without retaining test data.

## Financial privacy and expenses — October 15, 2026
`expenses` permits recording a company expense. `finance` is a separate owner-assigned capability; it is never a navigation tab and does not independently grant access to a section. Existing staff receive neither new permission automatically. Owners retain full access. Both the Next.js actions and Postgres enforce the current permissions. Expense entries record amount, currency, purpose, category and spending date; an authenticated database trigger stamps the real account identity and creation time, overriding client attribution. Entries are append-only. History and per-currency totals require expenses + finance. Staff without finance can submit an expense but cannot retrieve past entries or aggregates.
CRM table RLS now requires crm + finance, preventing direct table/aggregate access to hidden balances. A private scoped helper provides CRM lists with financial values replaced by fixed placeholders for nonfinancial staff. Its whitelist-only save helper edits public customer fields without touching existing balances/currency. A separate scoped conversion helper preserves request conversion and its uniqueness constraint. Public wrappers run as invoker, helpers reside in the non-exposed redom_private schema with explicit EXECUTE grants, fixed search paths and authenticated scope checks. Client totals remain cumulative paid values, not a new payment ledger. Totals group currencies separately.
Release finance-expenses-setup.sql together with the matching Next.js source and updated admin-team Edge Function. The SQL was validated against PostgreSQL in an isolated PGlite database using the existing CRM/staff schema; connector transaction tests returned expired-request errors, so this release has not been applied to production yet.
